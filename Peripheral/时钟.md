
**STM32 时钟系统**理解成一句话**芯片里所有“会动的东西”都需要时钟，RCC 就是在决定“时钟从哪里来、变成多快、送给谁”。**

可以先看总图：

```
时钟源
  │
  ├── HSI  内部高速
  ├── HSE  外部高速
  ├── LSI  内部低速
  └── LSE  外部低速
        │
        ↓
       PLL
   倍频 / 分频
        │
        ↓
      SYSCLK
        │
        ↓
       AHB
        │
   ┌────┴────┐
   ↓         ↓
  APB1      APB2
   │         │
 外设时钟   外设时钟
```

# 1 晶振

STM32F4 的系统时钟可以来自 HSI、HSE 或 PLL。很多 STM32F407 开发板使用 8 MHz 外部晶振作为 HSE，再通过 PLL 得到 168 MHz，但 **HSE 的频率取决于具体硬件设计，并不固定为 8 MHz**。

不过这里面有一个很有意思的“幕后故事”：芯片内部的 CPU 和外设其实嫌 8MHz 实在是太慢了（STM32F407 最高需要 168MHz 的速度），它们不能直接用这个 8MHz 慢吞吞地工作，而是要靠 **PLL（锁相环）** 进行疯狂的“倍频”放大，再分发给各个器官。

可以把 STM32F4 的时钟运作方式拆解为以下三个核心事实：

1. 为什么要选 8MHz？（因为它最稳定、最经济）

外部晶振（硬件上叫 **HSE，High Speed External clock**）由于是石英材质的物理振荡器，受温度影响极小，频率**极其精准和稳定**。

- 选择 8MHz 是半导体行业的一个经典折中：它既不会太高导致电路板上的高频噪声太大，也不会太低导致倍频电路太难设计。市面上绝大多数 STM32 开发板（如正点原子、野火等）默认焊接的都是 **8MHz 的金属外壳晶振**。

---

2. 8MHz 进来后，是如何“变身”驱动全身的？

使用**PLL（分频再倍频）** 。以 STM32F407 芯片（最高主频 168MHz）为例，官方推荐的经典时钟配置流程（时钟树）通常是这样的：

1. **输入 8MHz 外部晶振**。
2. **先分频（M=8）：** 8MHz 经过 M 分频器除以 8，变成 **1MHz**。这个 1MHz 就是极度精准的“基准步长”。
3. **再倍频（N=336）：** 1MHz 的基准信号送入 PLL 反馈环路，乘以 N（336倍），瞬间飙升到 **336MHz**（这就是 VCO 发动机的全力输出）。
4. **输出分频（P=2）：** 336MHz 再经过系统分频器除以 2，最终得到 **168MHz** 的超高速主频，直接送给 **Cortex-M4 内核（CPU）**，让它每秒能执行上亿条指令！
5. **分发给其他外设：**
    - 336MHz 除以 7 得到 **48MHz**，专门送给 **USB 接口**（USB 协议死规定必须用 48MHz）。
    - 168MHz 再经过不同程度的分频，变成几十 MHz 送给 **GPIO、串口（UART）、I2C、SPI、ADC** 等外设。

也就是说，外部的 8MHz 就像一滴**高纯度的原液**，被 PLL 放大并稀释成了各种浓度的时钟信号，供芯片全身使用。

---

3. 特殊情况：没有 8MHz 外部晶振，芯片还能活吗？

   **能活，但活得不够好。** STM32F4 内部其实自带了一个**内置的 RC 振荡器（叫 HSI，High Speed Internal clock）**，频率是 **16MHz**。

- **刚上电时：** 芯片还没加载你的代码，它不确定外面有没有焊接晶振。为了安全，它会**默认使用内部的 16MHz（HSI）** 先启动。
- **代码运行后：** 配置代码（如 `SystemClock_Config`）会下令切换到外部 8MHz 晶振，并开启 PLL。
- **不一直用内部的 16MHz** 内部的 RC 振荡器是靠芯片内部的电容充放电实现的，受**温度和电压**影响非常大。如果芯片发热，16MHz 可能会变成 15.8MHz 或 16.2MHz。这种微小的抖动会导致**串口通信乱码、CAN总线报错、或者通信直接崩掉**。对时钟精度要求较高的应用，通常更倾向使用精度更高的外部时钟源。是否必须使用 HSE，要根据通信协议、系统精度、成本、功耗和硬件设计要求决定。

# 2 MCU 时钟

CPU 本质上是一堆数字逻辑。比如执行`a = b + c;`CPU 不可能“随时随地一起执行”。它需要一个节拍：

```text
滴
→ 取指令

滴
→ 解码

滴
→ 执行

滴
→ 写回
```

这个“滴滴滴”的节拍就是Clock，如果 CPU 时钟是168 MHz意思是1 秒钟大约有 1.68 亿个时钟周期
注意不是说 1 秒一定执行 1.68 亿条 C 语句。一条机器指令可能需要一个或多个周期。

## 2.1 HSI 

HSI：High Speed Internal 内部高速时钟也就是**芯片里面自己带的 RC 振荡器**。优点：

```text
不用外部晶振
上电就能用
启动快
成本低
```

缺点：

```text
精度一般
温漂更明显
```

STM32F4 常见：

```
HSI = 16 MHz
```

所以 MCU 刚复位时，经常先依赖内部时钟工作。

## 2.2 HSE 

HSE：`High Speed External` 外部高速时钟，一般来自：

```
外部晶振
或
外部时钟源
```

比如开发板上常见：8 MHz、25 MHz它通常比 HSI更稳定、更精确。所以如果后面想得到`168 MHz SYSCLK`，就可以：

```
8 MHz HSE
↓
PLL
↓
168 MHz
```

## 2.3 LSI / LSE

LSI：

```
Low Speed Internal
内部低速时钟
```

**一般精度不高，但省事**。常用于独立看门狗 IWDG

LSE：

```
Low Speed External
外部低速晶振
```

最典型32.768 kHz为什么总是这个奇怪的数？因为`32768 = 2^15`连续除以 2：

```
32768
↓ /2
16384
↓
8192
...
↓
1 Hz
```

特别适合：RTC、实时时钟

# 3 PLL

PLL：Phase Locked Loop 锁相环。从嵌入式软件角度，可以把它理解成**时钟倍频/分频机器。** 比如HSE = 8 MHz 通过 PLL：

```
8 MHz
↓
先除
↓
倍频
↓
再除
↓
168 MHz
```

STM32F4 常见计算形式：

$$f_{VCOin}=\frac{f_{PLLsource}}{PLLM}$$ $$f_{VCO}=f_{VCOin}\times PLLN$$

系统时钟：$f_{PLLCLK}=\frac{f_{VCO}}{PLLP}$

48 MHz 域：$f_{PLL48CLK}=\frac{f_{VCO}}{PLLQ}$ 

举个典型例子：

```
HSE = 8 MHz

PLL_M = 8
PLL_N = 336
PLL_P = 2
```

那么`8 / 8 = 1 MHz`，然后`1 × 336 = 336 MHz`，再`336 / 2 = 168 MHz`，于是`SYSCLK = 168 MHz`这就是 STM32F407 很经典的一套配置。

1. PLL 的四大核心组建（赛车系统比喻）

   在了解它怎么变频之前，先认识它的 4 个内部硬件： 

- **鉴相器（PFD）：** 裁判。负责对比两个输入信号的“相位/频率”是否一致。
- **低通滤波器（LPF）：** 裁判的传话筒。把裁判的判决（脉冲信号）平滑地变成一个稳定的**控制电压**。
- **压控振荡器（VCO）：** 赛车（核心发动机）。**它的输出频率完全由输入的电压决定**。电压越高，它抖动（振荡）得越快，输出频率就越高。
- **分频器（Divider）：** 减速齿轮（通常由计数器实现）。输入进去一个高频信号，出来一个低频信号。 

---

2. 核心魔法：为什么在反馈端“分频”就能实现“倍频”？

这就是 PLL 的闭环控制逻辑。假设目标是：把一个 **10MHz 的晶振输入**，放大 5 倍，变成 **50MHz**。 

步骤一：在反馈回路里放置“5分频器” ,把分频器（假设分频系数𝑁=5）放在 **VCO 的输出端** 和 **鉴相器（裁判）的输入端** 之间。 

```
              +--------+      +--------+      +--------+
输入(10MHz)--> | 鉴相器 | ---> | 滤波器 | ---> |  VCO   | --+--> 输出(目标50MHz)
              | (PFD)  |      |  (LPF) |     | (压控)  |   |
               +--------+      +--------+      +--------+  |
                   ^                                       |
                   |          +------------+               |
                   +--------- | 5分频器(N=5)| <-------------+
                              +------------+
```

步骤二：动态锁定的全过程（系统如何自我调整） 

1. **刚开机时：** VCO 刚启动，假设它此时胡乱输出了一个 **30MHz** 的频率。 
2. **反馈分频：** 这个 30MHz 经过反馈路径上的“5分频器”，变成了![](data:image/gif;base64,R0lGODlhAQABAIAAAP///wAAACH5BAEAAAAALAAAAAABAAEAAAICRAEAOw==)30![](data:image/gif;base64,R0lGODlhAQABAIAAAP///wAAACH5BAEAAAAALAAAAAABAAEAAAICRAEAOw==)÷5![](data:image/gif;base64,R0lGODlhAQABAIAAAP///wAAACH5BAEAAAAALAAAAAABAAEAAAICRAEAOw==)=𝟔𝐌𝐇𝐳。 
3. **裁判对比：** 鉴相器（裁判）同时收到了两个信号：
    - 正确的参考信号：**10MHz**
    - 反馈回来的信号：**6MHz**
    - 裁判发现：反馈信号太慢了！于是裁判下达命令：“加速！” 
4. **电压升高：** 滤波器把“加速”命令变成**更高的电压**送给 VCO。 
5. **VCO 加速：** VCO 收到高电压，拼命加速，频率从 30MHz 飚升到了 **50MHz**。 
6. **最终锁定：**
    - 当 VCO 输出 **50MHz** 时，经过 5 分频，反馈给裁判的正好是![](data:image/gif;base64,R0lGODlhAQABAIAAAP///wAAACH5BAEAAAAALAAAAAABAAEAAAICRAEAOw==)50![](data:image/gif;base64,R0lGODlhAQABAIAAAP///wAAACH5BAEAAAAALAAAAAABAAEAAAICRAEAOw==)÷5![](data:image/gif;base64,R0lGODlhAQABAIAAAP///wAAACH5BAEAAAAALAAAAAABAAEAAAICRAEAOw==)=𝟏𝟎𝐌𝐇𝐳。
    - 裁判一看：参考信号是 10MHz，反馈也是 10MHz，两人完全同步（锁相）！
    - 裁判满意了，保持电压不再变化，VCO 稳定输出 **50MHz**。 

**结论：** 裁判（鉴相器）的本职工作是让两边的频率**相等**。只要你在反馈端放一个除以 5 的分频器，VCO 就必须把自己放大 5 倍，才能满足裁判的要求。**这就是“反馈分频 = 整体倍频”的数学魔法。** 

---

3. 那所谓的“先分频、再倍频”又是怎么回事？（输入端分频）

   在实际的单片机（如 STM32）中，外部晶振（比如 8MHz）进入 PLL 之前，通常还会经过一个**输入分频器（通常叫 M 分频）**。这又是为什么呢？ 

   因为 VCO（发动机）的调节范围是有限的，而且鉴相器（裁判）在面对太高的输入频率时会“看花眼”。 

   完整的 PLL 结构公式是这样的：最终输出频率 (VCO)=输入晶振频率÷𝑀×𝑁
- **M (输入分频)：** 先把输入的粗糙晶振频率切细。比如 8MHz 经过![](data:image/gif;base64,R0lGODlhAQABAIAAAP///wAAACH5BAEAAAAALAAAAAABAAEAAAICRAEAOw==)𝑀![](data:image/gif;base64,R0lGODlhAQABAIAAAP///wAAACH5BAEAAAAALAAAAAABAAEAAAICRAEAOw==)=2分频，变成一个 **4MHz** 的极其稳定的基准步长。
- **N (反馈倍频)：** 再利用上面讲的闭环反馈，乘以 N 倍。比如![](data:image/gif;base64,R0lGODlhAQABAIAAAP///wAAACH5BAEAAAAALAAAAAABAAEAAAICRAEAOw==)𝑁![](data:image/gif;base64,R0lGODlhAQABAIAAAP///wAAACH5BAEAAAAALAAAAAABAAEAAAICRAEAOw==)=40，那么最终输出就是![](data:image/gif;base64,R0lGODlhAQABAIAAAP///wAAACH5BAEAAAAALAAAAAABAAEAAAICRAEAOw==)4![](data:image/gif;base64,R0lGODlhAQABAIAAAP///wAAACH5BAEAAAAALAAAAAABAAEAAAICRAEAOw==)MHz![](data:image/gif;base64,R0lGODlhAQABAIAAAP///wAAACH5BAEAAAAALAAAAAABAAEAAAICRAEAOw==)×40![](data:image/gif;base64,R0lGODlhAQABAIAAAP///wAAACH5BAEAAAAALAAAAAABAAEAAAICRAEAOw==)=160![](data:image/gif;base64,R0lGODlhAQABAIAAAP///wAAACH5BAEAAAAALAAAAAABAAEAAAICRAEAOw==)MHz。 

  通过调节M和N，这两个数字，芯片就可以用同一个外部晶振，精准地配置出各种想要的奇葩频率（比如 48MHz 给 USB 用，72MHz 给 CPU 用）。 

总结

- **先分频（M）：** 是在**系统入口**把大步长切成小步长，方便后续精准微调。
- **再倍频（N）：** 是把分频器藏在**反馈屁股后面**去欺骗裁判，逼迫内部发动机（VCO）输出成倍放大的高频时钟。 

# 4 SYSCLK

SYSCLK：

```
System Clock
系统时钟
```

可以理解成**芯片整个系统最核心的主时钟**。它通常可以来自：

```
HSI
HSE
PLL
```

比如SYSCLK = 168 MHz但不是所有外设都直接跑 168 MHz。接下来还要分频。

# 5 AHB

SYSCLK 往下：

```
SYSCLK
↓
AHB Prescaler
↓
HCLK
```

HCLK 主要给：

```
CPU
AHB总线
DMA
GPIO
CRC
Flash接口等
```

比如：

```
SYSCLK = 168 MHz
AHB prescaler = 1
```

那么：

```
HCLK = 168 MHz
```

所以写`RCC_AHB1PeriphClockCmd(RCC_AHB1Periph_CRC, ENABLE);`就是打开 AHB1 上 CRC 外设的时钟门。

# 6 APB1 和 APB2

AHB 再往下分：

```
HCLK
↓
APB1
↓
PCLK1

HCLK
↓
APB2
↓
PCLK2
```

在 STM32F407 常见：

```
HCLK  = 168 MHz
PCLK1 = 42 MHz
PCLK2 = 84 MHz
```

为什么不能都跑 168 MHz？

因为**不同总线和外设有自己的最高频率限制**。所以需要分频。


挂 APB1和挂 APB2

APB1 常见：

```text
USART2
USART3
UART4
UART5
I2C
SPI2
SPI3
TIM2~TIM7
```

APB2 常见：

```text
USART1
USART6
SPI1
TIM1
TIM8
ADC
SYSCFG
```


# 7 USART 波特率和时钟

配置`USART1 = 115200`并不是 USART 自己“凭空产生”115200。它其实是：

```text
PCLK2
↓
USART分频器
↓
115200
```

所以如果PCLK2 配错，哪怕 BRR 配置公式本身没错实际波特率也会错。结果可能：

```text
串口乱码
收不到数据
帧错误
```

所以以后调 USART 不通，除了看：

```text
GPIO
BRR
RXNE
DMA
```

也要想到时钟对不对

---

# 8 Timer 时钟

假设APB1 = 42 MHz，不能直接说TIM2 = 42 MHz。STM32F4 常见规则：

```text
如果 APB prescaler = 1
Timer clock = PCLK

如果 APB prescaler > 1
Timer clock = 2 × PCLK
```

例如：

```
PCLK1 = 42 MHz
APB1 prescaler = 4
```

那么很多 APB1 Timer：TIM clock = 84 MHz这就是为什么：

```
APB1 = 42 MHz
TIM2可能是84 MHz
```

---

# 9 SysTick 和时钟

SysTick 是 Cortex-M 内核里的系统定时器。FreeRTOS 会大量碰到。比如SysTick每1ms触发一次，本质就是：

```
某个系统时钟
↓
SysTick重装值
↓
1ms中断
```

所以SystemCoreClock如果配置错：

```
HAL_Delay
FreeRTOS Tick
时间计算
```

都可能不准。这就是为什么时钟系统和 FreeRTOS 是直接相关的。

---

# 10 每个外设要“开时钟”

比如`RCC_APB2PeriphClockCmd(RCC_APB2Periph_USART1, ENABLE);`很多初学者会问SYSCLK 不是已经有了吗，为什么 USART1 还要再 enable？因为芯片为了省功耗，会有`Clock Gate`时钟门控，默认**某些外设没有时钟**，就像总电源开着，但是房间灯开关没开。所以：

```text
SYSCLK存在
≠
所有外设都在运行
```

必须：

```
RCC
↓
enable peripheral clock
```

之后 USART/GPIO/DMA 才真正工作。

---

# 11 RCC 

RCC：Reset and Clock Control。它主要负责：

```text
选择时钟源
配置PLL
配置AHB/APB分频
打开/关闭外设时钟
外设复位
```

所以可以直接理解**RCC = STM32 的时钟总管。** 以后看到：

```
RCC_AHB1PeriphClockCmd()
RCC_APB1PeriphClockCmd()
RCC_APB2PeriphClockCmd()
```

本质都在操作 RCC 寄存器。

---

# 12 SystemInit() 和时钟

系统启动的时候：

```text
Reset_Handler
↓
SystemInit()
↓
__main
↓
main()
```

`SystemInit()` 里面通常会干：

```text
配置RCC
配置PLL
配置系统时钟
设置VTOR等
```

所以168 MHz很多时候并不是 `main()` 里才设置的。而是在main之前就已经完成了。

# 13 Clock Tree 

Clock Tree 就是**一张时钟从源头一路分到 CPU 和各个外设的路线图**。例如：

```text
               HSI
                │
                ├──────────┐
                │          │
               HSE         │
                │          │
                └──→ PLL ──┤
                           ↓
                         SYSCLK
                           │
                     AHB Prescaler
                           │
                         HCLK
                  ┌────────┼────────┐
                  │        │        │
                 CPU      DMA     AHB外设
                  │
             ┌────┴─────┐
             ↓          ↓
       APB1 Prescaler APB2 Prescaler
             ↓          ↓
           PCLK1       PCLK2
             ↓          ↓
        APB1外设      APB2外设
```


# 14 面试

- 如果面试官问 STM32 时钟源有哪些？

答：

```
HSI
HSE
LSI
LSE
PLL
```

- 如果问USART1 波特率和哪个时钟有关？

要知道：

```
USART1通常挂APB2
所以和PCLK2有关
```

- 如果问APB1 = 42 MHz，TIM2 一定是42MHz吗？

答：

> 不一定。如果 APB prescaler > 1，STM32F4 的 Timer clock 通常是 PCLK 的两倍，所以可能是 84 MHz。

- 如果问为什么使用外部晶振？

可以答：

> 外部晶振通常精度和稳定性更好，对精确通信、USB、RTC 等应用更有优势。

- 如果问为什么要先打开 RCC 外设时钟？

答：

> STM32 为了降低功耗会对外设进行 clock gating，未打开对应外设时钟时，外设逻辑不工作，因此初始化 GPIO、USART、DMA 等之前要先通过 RCC 使能对应总线时钟。
