
**STM32 时钟系统**理解成一句话**芯片里所有“会动的东西”都需要时钟，RCC 就是在决定“时钟从哪里来、变成多快、送给谁”。**

可以先看总图：

```
时钟源
  │
  ├── HSI  内部高速
  ├── HSE  外部高速
  ├── LSI  内部低速
  └── LSE  外部低速
        │
        ↓
       PLL
   倍频 / 分频
        │
        ↓
      SYSCLK
        │
        ↓
       AHB
        │
   ┌────┴────┐
   ↓         ↓
  APB1      APB2
   │         │
 外设时钟   外设时钟
```

#  MCU 需要时钟

CPU 本质上是一堆数字逻辑。比如执行`a = b + c;`CPU 不可能“随时随地一起执行”。它需要一个节拍：

```text
滴
→ 取指令

滴
→ 解码

滴
→ 执行

滴
→ 写回
```

这个“滴滴滴”的节拍就是Clock，如果 CPU 时钟是168 MHz意思是1 秒钟大约有 1.68 亿个时钟周期
注意不是说 1 秒一定执行 1.68 亿条 C 语句。一条机器指令可能需要一个或多个周期。

# HSI 是什么

HSIHigh Speed Internal 内部高速时钟也就是芯片里面自己带的 RC 振荡器。优点：

```text
不用外部晶振
上电就能用
启动快
成本低
```

缺点：

```text
精度一般
温漂更明显
```

STM32F4 常见：

```
HSI = 16 MHz
```

所以 MCU 刚复位时，经常先依赖内部时钟工作。

---

# 3. HSE 是什么

HSE：

```
High Speed External
外部高速时钟
```

一般来自：

```
外部晶振
或
外部时钟源
```

比如开发板上常见：

```
8 MHz
25 MHz
```

它通常比 HSI：

```
更稳定
更精确
```

所以如果你后面想得到：

```
168 MHz SYSCLK
```

就可以：

```
8 MHz HSE
↓
PLL
↓
168 MHz
```

---

# 4. LSI / LSE 是什么

LSI：

```
Low Speed Internal
内部低速时钟
```

一般精度不高，但省事。

常用于：

```
独立看门狗 IWDG
```

LSE：

```
Low Speed External
外部低速晶振
```

最典型：

```
32.768 kHz
```

为什么总是这个奇怪的数？

因为：

```
32768 = 2^15
```

连续除以 2：

```
32768
↓ /2
16384
↓
8192
...
↓
1 Hz
```

特别适合：

```
RTC
实时时钟
```

---

# 5. PLL 是什么

PLL：

```
Phase Locked Loop
锁相环
```

你当前不用深入模拟原理。

从嵌入式软件角度，你可以把它理解成：

> **时钟倍频/分频机器。**

比如：

```
HSE = 8 MHz
```

通过 PLL：

```
8 MHz
↓
先除
↓
倍频
↓
再除
↓
168 MHz
```

STM32F4 常见计算形式：

```
PLL输入 = HSE / PLL_M

VCO = PLL输入 × PLL_N

SYSCLK = VCO / PLL_P
```

举个典型例子：

```
HSE = 8 MHz

PLL_M = 8
PLL_N = 336
PLL_P = 2
```

那么：

```
8 / 8 = 1 MHz
```

然后：

```
1 × 336 = 336 MHz
```

再：

```
336 / 2 = 168 MHz
```

于是：

```
SYSCLK = 168 MHz
```

这就是 STM32F407 很经典的一套配置。

---

# 6. SYSCLK 是什么

SYSCLK：

```
System Clock
系统时钟
```

可以理解成：

> 芯片整个系统最核心的主时钟。

它通常可以来自：

```
HSI
HSE
PLL
```

比如：

```
SYSCLK = 168 MHz
```

但不是所有外设都直接跑 168 MHz。

接下来还要分频。

---

# 7. AHB 是什么

SYSCLK 往下：

```
SYSCLK
↓
AHB Prescaler
↓
HCLK
```

HCLK 主要给：

```
CPU
AHB总线
DMA
GPIO
CRC
Flash接口等
```

比如：

```
SYSCLK = 168 MHz
AHB prescaler = 1
```

那么：

```
HCLK = 168 MHz
```

所以你以前写：

```
RCC_AHB1PeriphClockCmd(RCC_AHB1Periph_CRC, ENABLE);
```

就是：

> 打开 AHB1 上 CRC 外设的时钟门。

---

# 8. APB1 和 APB2

AHB 再往下分：

```
HCLK
↓
APB1
↓
PCLK1

HCLK
↓
APB2
↓
PCLK2
```

在 STM32F407 常见：

```
HCLK  = 168 MHz
PCLK1 = 42 MHz
PCLK2 = 84 MHz
```

为什么不能都跑 168 MHz？

因为：

> 不同总线和外设有自己的最高频率限制。

所以需要分频。

---

# 9. 哪些外设挂 APB1，哪些挂 APB2

你不用死背全部，但常见要知道。

APB1 常见：

```
USART2
USART3
UART4
UART5
I2C
SPI2
SPI3
TIM2~TIM7
```

APB2 常见：

```
USART1
USART6
SPI1
TIM1
TIM8
ADC
SYSCFG
```

所以你现在用：

```
USART1
```

它通常挂：

```
APB2
```

因此波特率来源和：

```
PCLK2
```

有关。

---

# 10. USART 波特率为什么和时钟有关

你配置：

```
USART1 = 115200
```

并不是 USART 自己“凭空产生”115200。

它其实是：

```
PCLK2
↓
USART分频器
↓
115200
```

所以如果：

```
PCLK2 配错
```

哪怕你 BRR 配置公式本身没错：

```
实际波特率也会错
```

结果可能：

```
串口乱码
收不到数据
帧错误
```

所以以后你调 USART 不通，除了看：

```
GPIO
BRR
RXNE
DMA
```

也要想到：

> 时钟对不对？

---

# 11. 为什么 Timer 时钟比较特殊

这个是 STM32 高频面试点。

假设：

```
APB1 = 42 MHz
```

你不能直接说：

```
TIM2 = 42 MHz
```

STM32F4 常见规则：

```
如果 APB prescaler = 1
Timer clock = PCLK

如果 APB prescaler > 1
Timer clock = 2 × PCLK
```

例如：

```
PCLK1 = 42 MHz
APB1 prescaler = 4
```

那么很多 APB1 Timer：

```
TIM clock = 84 MHz
```

这就是为什么：

```
APB1 = 42 MHz
TIM2可能是84 MHz
```

---

# 12. SysTick 和时钟

SysTick 是 Cortex-M 内核里的系统定时器。

你以后 FreeRTOS 会大量碰到。

比如：

```
SysTick每1ms触发一次
```

本质就是：

```
某个系统时钟
↓
SysTick重装值
↓
1ms中断
```

所以：

```
SystemCoreClock
```

如果配置错：

```
HAL_Delay
FreeRTOS Tick
时间计算
```

都可能不准。

这就是为什么时钟系统和 FreeRTOS 是直接相关的。

---

# 13. 为什么每个外设还要“开时钟”

比如：

```
RCC_APB2PeriphClockCmd(RCC_APB2Periph_USART1, ENABLE);
```

很多初学者会问：

> SYSCLK 不是已经有了吗，为什么 USART1 还要再 enable？

因为芯片为了省功耗，会有：

```
Clock Gate
时钟门控
```

默认：

```
某些外设没有时钟
```

就像：

```
总电源开着
但是房间灯开关没开
```

所以：

```
SYSCLK存在
≠
所有外设都在运行
```

你必须：

```
RCC
↓
enable peripheral clock
```

之后 USART/GPIO/DMA 才真正工作。

---

# 14. RCC 是什么

RCC：

```
Reset and Clock Control
```

它主要负责：

```
选择时钟源
配置PLL
配置AHB/APB分频
打开/关闭外设时钟
外设复位
```

所以你可以直接理解：

> **RCC = STM32 的时钟总管。**

你以后看到：

```
RCC_AHB1PeriphClockCmd()
RCC_APB1PeriphClockCmd()
RCC_APB2PeriphClockCmd()
```

本质都在操作 RCC 寄存器。

---

# 15. SystemInit() 和时钟的关系

你前面 Bootloader 学过：

```
Reset_Handler
↓
SystemInit()
↓
__main
↓
main()
```

SystemInit() 里面通常会干：

```
配置RCC
配置PLL
配置系统时钟
设置VTOR等
```

所以你的：

```
168 MHz
```

很多时候并不是 `main()` 里才设置的。

而是在：

```
main之前
```

就已经完成了。

这也是为什么你前面 MAP 和 startup 学习跟时钟也能串起来。

---

# 16. Clock Tree 是什么

Clock Tree 就是一张：

> 时钟从源头一路分到 CPU 和各个外设的路线图。

例如：

```
        HSE 8MHz
           │
           ↓
          PLL
           │
        168MHz
           │
        SYSCLK
           │
          AHB
           │
       HCLK 168MHz
        /       \
       /         \
   APB1           APB2
   42MHz          84MHz
     │              │
 USART2           USART1
 TIM2             TIM1
```

你以后看到 CubeMX 的 Clock Configuration 页面，本质就是这张图。

# 18. 面试你至少要能答这些

如果面试官问：

> STM32 时钟源有哪些？

你答：

```
HSI
HSE
LSI
LSE
PLL
```

如果问：

> USART1 波特率和哪个时钟有关？

你要知道：

```
USART1通常挂APB2
所以和PCLK2有关
```

如果问：

> APB1 = 42 MHz，TIM2 一定是42MHz吗？

答：

> 不一定。如果 APB prescaler > 1，STM32F4 的 Timer clock 通常是 PCLK 的两倍，所以可能是 84 MHz。

如果问：

> 为什么使用外部晶振？

可以答：

> 外部晶振通常精度和稳定性更好，对精确通信、USB、RTC 等应用更有优势。

如果问：

> 为什么要先打开 RCC 外设时钟？

答：

> STM32 为了降低功耗会对外设进行 clock gating，未打开对应外设时钟时，外设逻辑不工作，因此初始化 GPIO、USART、DMA 等之前要先通过 RCC 使能对应总线时钟。

---

你现在不用先背 RCC 所有寄存器。最重要的是把这条链真正记住：

```
晶振/内部RC
↓
PLL
↓
SYSCLK
↓
HCLK
↓
PCLK1 / PCLK2
↓
具体外设
```
