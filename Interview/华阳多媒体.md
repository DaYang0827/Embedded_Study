# 一、今天 Bootloader 他们最可能怎么问

你不用再背几十题，只掌握这一条主线：


### 1. 为什么用 Ring Buffer？

回答：

> UART 数据到达和主程序处理速度可能不一致，所以我用 Ring Buffer 把接收和处理解耦。中断中只负责快速入队，主循环再做协议解析和 Flash 操作，从而减少 ISR 执行时间，也降低后续数据丢失的风险。

如果追问：

> 满了怎么办？

说：

> 当前实现会让写入函数返回失败；更完整的工程里可以设置 overflow 标志、丢弃当前异常帧并重新同步，或者在协议层增加流控。

---

### 2. 为什么不能在 UART 中断里写 Flash？

> Flash 擦写比较耗时，如果直接放在 ISR 中，会让中断执行时间过长，同时影响其他中断以及后续 UART 数据接收。所以中断只负责搬数据，耗时处理放到主流程。

这题很符合汽车 MCU 岗思路。

---

### 3. Flash 怎么分区？

你只记：

```
Bootloader
Firmware Info
APP
```

回答：

> STM32F4 的 Flash 擦除是按 Sector 进行，所以分区时需要考虑 Sector 边界。Bootloader 和 APP 分开，避免升级 APP 时误擦 Bootloader，同时单独留固件信息区保存 Magic Number、长度和 CRC。

你简历里确实已经明确做到 Boot、固件信息和 APP 分区。 郝月赫-嵌入式软件工程师-2026秋招

---

### 4. APP 怎么跳？

背两个东西：

```
APP[0]     = MSP
APP[0] + 4 = Reset_Handler
```

回答：

> APP 起始位置是中断向量表，第一个 word 是初始 MSP，第二个 word 是 Reset_Handler。跳转前我先检查 MSP 是否位于 SRAM 合法范围、Reset_Handler 是否位于 APP Flash，然后关闭 Bootloader 遗留中断和 SysTick、重定位 VTOR、设置 MSP，最后跳 Reset_Handler。

---

### 5. 为什么不能直接跳 `main()`？

> 因为 APP 在进入 main 之前还有启动过程，包括 C 运行环境初始化、`.data` 搬运、`.bss` 清零以及 SystemInit 等。如果直接跳 main，可能绕过这些初始化，所以应该跳 Reset_Handler。

# 四、DMA 大概率会问

你的简历写了 DMA，所以一定要能答。

### DMA 是什么？

> DMA 可以在外设和内存之间直接搬运数据，CPU 只负责配置和处理传输完成事件，不需要每个字节都由 CPU 搬运。

### UART + DMA 和 UART 中断逐字节接收有什么区别？

> UART 字节中断每收到一个字节都需要 CPU 进入 ISR；DMA 可以一次搬运一块数据，CPU 占用更低，更适合连续数据流。

### DMA 是否完全不需要 CPU？

> 不是。CPU 仍然需要配置 DMA、处理完成/半完成/错误中断，并消费接收到的数据。

# 五、FreeRTOS 今天准备 5 题就够

### Task 怎么切换？

> 调度器根据任务优先级和就绪状态选择任务运行，切换时保存当前任务上下文到其栈中，并恢复下一个任务的上下文。

### Queue 是干嘛的？

> 用于任务之间或者 ISR 和任务之间安全传递数据。

### Semaphore 和 Queue 区别？

> Queue 重点是传数据；Semaphore 重点是同步或计数。

### Mutex 为什么和二值信号量不完全一样？

> Mutex 主要用于共享资源互斥，一般带优先级继承，用于缓解优先级反转。

### ISR 能不能直接用普通 `xQueueSend()`？

> 不应该，FreeRTOS 在 ISR 中需要使用 `xQueueSendFromISR()` 这类专用 API。

## 你先掌握这些

### CAN 是什么？

> CAN 是面向汽车和工业控制的多节点串行总线，采用差分信号 CAN_H/CAN_L，具有较强抗干扰能力，并支持多主通信。

### CAN 没有传统“设备地址”

CAN 帧核心是：

> **Identifier。**

节点根据 ID 决定是否接收。

---

### CAN 怎么仲裁？

这是最容易问的。

CAN：

```
0 = dominant 显性
1 = recessive 隐性
```

多个节点同时发时：

> 边发送边监听总线。

如果自己发 `1`，却读到 `0`：

> 说明自己输掉仲裁，停止发送。

因此：

> **数值更小的 ID 优先级通常更高。**

---

### CAN 为什么可靠？

可以说：

> 差分传输 + CRC + ACK + 位监测 + 位填充检查 + 自动重发 + 错误计数与错误状态管理。

不用展开所有细节。
